An index line, handoff bullet or brief records WHAT a constraint says and drops WHO asked for it. A peer's request ("warn us before this ships") and an operator's instruction ("do not ship this") read almost identically once compressed, but they license completely different actions. Once the author is gone, a request reliably drifts upward into a mandate, because treating a request as binding looks like diligence and nothing pushes back.

Measured twice in the same week. A "change freeze" that four sessions obeyed for hours — deferring two confirmed live defects and a deterministic data-loss fix — originated in one agent asking another to be warned before shipping; the source file said so in its own original wording and every reader skipped that sentence. In a second thread the same request was restated as an operator-imposed freeze and propagated three hops into a branch's code comments.

**The mechanism that makes it invisible:** a false premise that prescribes the same conduct as the true one generates no feedback. "There is a freeze" and "warn them first" both produce careful behaviour, so nothing looks wrong and no suspicion arrives to trigger a check. The source check therefore has to be a standing habit, not a response to doubt.

**How to apply:**
- **Before treating a recorded constraint as the operator's, find the sentence naming who asked for it.** If a summary names no author, open the file. If you cannot find the sentence, say "the brief calls this a freeze", not "there is a freeze".
- **Authority is not inherited by restatement.** A rule relayed through a peer, however reliable the peer has been, is not an authorization: check the primary source instead of weighing the messenger.
- **When you find a constraint was never real, do not just delete it.** Work out the true obligation and write that in its place (here, a duty to notify rather than a bar on shipping). Deleting alone invites the opposite error later, from someone who believes there was never anything to respect. If the false version already reached a durable record, correct it with an entry on top rather than rewriting history ([[correct-a-durable-record-explicitly]]).
